# Recipes Project

Веб-приложение для публикации и поиска кулинарных рецептов. Серверная часть
предоставляет REST API, клиентская часть отображает каталог и формы работы
с рецептами и учётной записью.

## Возможности

- Регистрация, вход, выход и просмотр профиля пользователя.
- Просмотр каталога и отдельных рецептов.
- Поиск по названию, фильтрация по категориям и автору.
- Создание рецептов с описанием, шагами приготовления, ингредиентами и изображением.
- Просмотр своих рецептов, редактирование и удаление рецептов автором.
- Управление данными через административный интерфейс Django.

## Технологии

| Часть проекта | Технологии |
| --- | --- |
| Сервер | Python, Django 6.0, Django REST Framework |
| База данных | SQLite |
| Клиент | React 19, Vite 7, React Router, Material UI, Axios |
| Изображения | Django ImageField, Pillow |

## Структура

| Путь | Назначение |
| --- | --- |
| `config/` | Настройки Django, корневые маршруты и аутентификация |
| `recipes/` | Модели, сериализаторы и API рецептов, категорий и ингредиентов |
| `users/` | Регистрация, вход, выход и профиль |
| `frontend/` | Клиентское приложение React |
| `manage.py` | Команды управления Django |
| `requirements.txt` | Прямые зависимости серверной части |

## Требования

- Python 3.12–3.14 для Django 6.0.
- Node.js 22.12 или новее в ветке 22; Vite также допускает Node.js 20.19+ в ветке 20 и более новые версии Node.js согласно `frontend/package-lock.json`.
- npm и Git.

`requirements.txt` содержит прямые зависимости сервера, а не снимок исходного
Python-окружения. Django ограничен веткой 6.0; версии остальных Python-пакетов
не зафиксированы. Версии клиентских зависимостей сохранены в
`frontend/package-lock.json`.

## Локальный запуск в Linux

### Серверная часть

В корне клонированного репозитория:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python manage.py migrate
python manage.py check
python manage.py runserver 127.0.0.1:8000
```

На Kali, если модуль `venv` отсутствует, установите пакет `python3-venv`.
API доступен по адресу <http://localhost:8000/api/>. Например, список рецептов:
<http://localhost:8000/api/recipes/>. Корень `/api/` не содержит отдельной страницы.

### Клиентская часть

В другом терминале перейдите в каталог `frontend/` этого репозитория:

```bash
npm ci
npm run dev
```

Откройте <http://localhost:5173>. В `frontend/src/api/axios.js` задан адрес
API `http://localhost:8000/api`. Используйте `localhost` для клиентского сайта
и API последовательно, поскольку вход пользователя использует cookies.

### Административный интерфейс

В корне проекта с активированным `.venv` выполните:

```bash
python manage.py createsuperuser
```

При работающем сервере откройте <http://localhost:8000/admin/>.
Категории и ингредиенты можно добавить через административный интерфейс.
База SQLite и загруженные изображения создаются локально и не входят в репозиторий.

## Дополнительные команды

В корне проекта с активированным `.venv`:

```bash
python manage.py check
python manage.py test
```

В каталоге `frontend/`:

```bash
npm run lint
npm run build
```

Наличие команды запуска тестов не означает, что проект имеет полное тестовое покрытие.

## Настройки разработки

Текущая конфигурация рассчитана на локальную учебную разработку: включён
`DEBUG`, разрешён CORS для всех источников, ослаблены настройки cookies
и отключены отдельные проверки CSRF. `SECRET_KEY` задан в `config/settings.py`.
Эти настройки требуют пересмотра перед размещением приложения в интернете.

Файлы `.env` исключены из Git, но текущий код не загружает их автоматически.
Перенос секретов в переменные окружения требует отдельного изменения настроек.
Уже опубликованный ключ нельзя считать секретным: для реального развёртывания
необходимо использовать новый ключ вне репозитория. `.gitignore` не удаляет
ранее закоммиченные данные и историю Git.
